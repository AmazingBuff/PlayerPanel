# Changelog

## [Unreleased]

### Added

- Add a non-persistent preview character that mirrors the player's supported appearance and worn equipment.
- Add a hotkey panel that renders the preview character and its worn equipment into a window with its own camera and lighting.
- Add mouse dragging and a saved position to the preview panel, and size the panel from the render height so it reads the same on 16:9, 21:9 and 32:9 screens.
- Add SWF-driven panel chrome: the panel now loads a swappable `Interface\PlayerPanel\panel.swf` through a registered menu, so UI reskins can restyle it without touching game logic. A skin supplies the panel's own opaque backdrop and its frame, the character is composited with straight alpha over the chrome the engine has already drawn and inset by the configured `PanelSkinInsetFraction`, and the skin's frame is never overdrawn.
- Add `tools/make_panel_swf.py`, a standard-library generator that produces and re-parses the default panel skin SWF.

### Changed

- Change the hotkey to toggle the preview character instead of the plugin master switch.
- Change the panel sizing and margin configuration keys to fractions; the previous absolute pixel keys are ignored and reported once in the log.
- Change the panel to use the game's own menu input and cursor instead of the plugin-managed cursor and look freeze.
- Change the `PanelCursorSensitivity` key to be ignored and reported once in the log, now that the panel follows the game's own menu cursor.
- Change the built-in dark fill and hairline border to be the panel's fallback chrome, used when no skin movie is available.
- Change the panel's character composite to alpha-blend over a skin's chrome instead of painting an opaque rectangle, so a skin's backdrop and frame stay visible behind and around the character; the skin inset is now its own validated `PanelSkinInsetFraction` key rather than the built-in hairline.

- Fix a render-thread crash when an engine object's D3D views die between collection and draw (observed under RenderDoc as a heap fault inside a hooked `VSSetShader`, with a `BSDismemberSkinInstance` in the registers): the panel borrowed the vertex buffer, index buffer and diffuse SRV from engine objects on the game thread and passed them to the D3D context on the render thread without holding references, so an engine-side destruction in between left dangling COM pointers. The borrowed objects are now AddRef'd at collection and Released right after the draw; the draw-side `PanelDraw` documents the ownership.

- Harden the collection against engine-side destruction races: a weapon blood decal ("BloodLighting") was destroyed on another thread while the panel read its shader property, and the texture's renderer data returned a garbage SRV pointer that crashed the new AddRef. Both collectors now take a NiPointer to the geometry before any read, the static path holds the geometry before touching its buffers and material, the diffuse texture is read through a NiPointer taken before its renderer data is dereferenced, and a null renderer view yields the explicit no-texture marker instead of a garbage pointer.

- Stop caching D3D pointers across threads entirely: an engine mesh's renderer data can be invalidated (and its buffers released) without destroying the NiObject, so even AddRef'd-at-collection pointers dangled by draw time and faulted inside d3d11. The draw list now stores only the engine-side renderer-data pointer - kept valid by the draw's NiPointers - and the render thread resolves the vertex/index buffers and the diffuse SRV from it immediately before each draw, with null checks that skip a released mesh instead of crashing.
- Close the resolve-to-use reference window (the RenderDoc-only crash on panel open): the deferred D3D resolution read the current buffer/SRV pointers without holding a reference, and RenderDoc's serialized, slow-pathed call handling widened that window enough for an engine-side release to land between resolve and use. The resolution now takes a COM reference on the render thread itself - the same thread the engine destroys render objects on, so nothing can free the object between the reference and the draw - releases after the draw, and every early-exit path in between releases what it holds.

- Fix the Present-time renderer-data dereference (the crash on the panel hotkey): the deferred-resolution design dereferenced the engine's `BSGraphics::TriShape` at draw time, but the engine deletes that whole struct mid-frame (mesh unload/reload) while the draw's NiPointers only keep the NiAVObject shell - the read itself landed in freed memory. The resolution and AddRef return to the game-thread collection, the one moment the engine guarantees its renderer data is alive because it renders the same mesh that frame, with every race hardening from the previous rounds retained: NiPointer holds on the geometry at both collector entries and on the texture during the material read, geometry held before its material is touched, null checks on every D3D pointer, and Release after the present-time draw.

- Skip transient weapon blood decals ("BloodLighting" and any named-blood geometry) before any property read: the engine creates and destroys these additive splats on its own threads without reference-count protection our side can observe, and three crash sessions in a row faulted reading their shader property mid-destruction. They carry no place in a static portrait.

### Fixed

- Fix the panel never drawing: the shader compilation step had no caller, so the panel's passes initialised with no shaders and nothing was rendered.
- Fix the panel width double-converting the aspect into a fraction of the screen width: a default configuration produced a full-width band instead of the intended portrait window. The width is now the height times the aspect, rounded and clamped to the screen width.
- Fix a saved panel position collapsing to the screen's far edge: the stored fraction of the free space was multiplied by the free space again, so any dragged position other than zero resolved to the bottom-right corner. The fraction is now taken against the free space directly, the exact inverse of the drag's normalisation, so a dragged spot round-trips.
- Fix the panel camera uploading a transposed view-projection matrix: DirectXMath composes row-vector matrices while the panel shaders read `row_major` memory as `mul(matrix, column vector)`, so the composed matrix is transposed before upload, matching the column-vector layout the static and palette paths already use.
- Fix a crash on the preview hotkey: the engine's equip path (`AddWornItem`) looks the item's inventory entry and extra data up in the actor's own container, so equipping a base object that was never added dereferenced a garbage extra-list pointer. Worn items are now added with `AddObjectToContainer` and equipped through `ActorEquipManager::EquipObject`, the same order SKSE's own `EquipItemEx` uses.
- Fix runtime shader compilation failing with `error X3000`: HLSL does not accept C++ east-const declarations (`float4 const x`) or anonymous parameters (`ps_background_main(PS_IN)`). All shaders use west-const and named parameters, and the full entry-point set is now verified to compile before the DLL ships.
- Fix the default panel skin rendering nothing, twice over: the generator wrote the SWF header RECT's fields in corner order `(x0, y0, x1, y1)` while the spec's field order is `(x_min, x_max, y_min, y_max)`, so the movie declared a zero-width stage the engine scaled to nothing; and it wrote a shape edge record's `NumBits` as the raw bit count where the spec stores the count minus two, which desynchronised the shape's bit stream - a spec-correct player parsed the records into garbage coordinates that painted no pixel, so neither the backdrop nor the frame band ever reached the screen while the skin still counted as loaded and the built-in chrome stayed suppressed. The generator now writes both conventions correctly, its parser reads them back per spec, degenerate (zero-span) stage rectangles are rejected, and the generated stage, shape bounds and rendered pixels are asserted against the intended 320x480 chrome. The rendering proof was produced with JPEXS ffdec against the regenerated artifact; the default skin artifact is regenerated.
- Add skinned `BSDynamicTriShape` support, ported from the sibling Highlight-Lootable-Corpses collector: positionless partitions (FaceGen/morph dynamic meshes - the head and the RaceMenu-morphed body) rebuild their model-space positions from `BSDynamicTriShape::dynamicData` through the partition's vertexMap into a float4 stream that the render thread uploads as a second vertex stream, with the POSITION semantic fetched there and every other attribute staying in the partition buffer. The head and the body render now.
- Tighten the panel framing: the loose world bound of a standing humanoid (measured r=129 for a 128-unit body) fitted on both axes of a portrait panel pushed the camera back until the character read as a thumbnail. The camera now targets the body's middle above the reference origin and fits a capped radius on the vertical axis alone, so the character fills the window; `CameraDistance` still overrides the fit.
- Fix a crash on the first composite: the swap chain arriving at the present hook is another mod's proxy, and querying it for `IDXGISwapChain3` called into a proxy vtable slot that holds garbage. The plugin draws into slot 0 again, the one slot every present wrapper forwards.
- Suspend the skin movie. The content dump proved the engine's UI pass paints after the plugin's present-hook composite, so a loaded skin's opaque backdrop covered the panel content every frame - the "frame with nothing inside" report. The plugin now loads no movie and the built-in chrome (opaque fill, hairline border, character) applies until the composite can run after the UI pass or the chrome is painted by the composite itself; the skin path, its loader and the generated SWF stay in the tree for that revision.
- Fix the panel content drawing nothing: the shader alpha-tested every mesh's material alpha against the sampled diffuse alpha at a global threshold, but SSE's diffuse alpha channel usually stores a specular mask whose near-zero values are not transparency, so opaque meshes discarded wholesale and the panel showed only its chrome. The alpha handling now follows each mesh's own `NiAlphaProperty`: meshes with alpha testing cut out at the configured `AlphaTestThreshold`, meshes without it never discard and write an alpha of one.
- Add the first palette-gate rejection's values to the skinned census log line (`skinBoneCount` / `skinNumMatrices`), so a panel missing the character body can be diagnosed from the log alone instead of only counting rejected partitions.
- Fix the panel character never rendering: the world copy was culled from its first frame, and the engine latches a skin instance's bone-matrix count at the skin's first render submission, so a culled preview's skins all carried a zero count and the palette gate rejected every one of them (measured in game: `skinBoneCount=46`, `skinNumMatrices=0`). The cull now waits for the first collection that carries skinned draws - one rendered frame after the preview's 3D loads - or a bounded grace, so a preview the player never faces is still hidden.
- Fix the preview wearing its duplicated base's default outfit: a placed preview appeared carrying an unrecognised daedric sword and scabbard. The duplicate's default outfit is cleared before placement, so the preview wears exactly the equipment the sync applies from the player's own worn list.
- The first composite draw now logs on its own flag: prepare() set the shared per-session diagnostics flag first, which suppressed the composite's line forever and left a silent composite failure unprovable from the log. The one-shot diagnostics also report the preview's world bound, and each collected draw reports its material alpha and UV flag.
- Fix the empty panel window (chrome drawn, character never): the geometry pass moved to drawing directly onto the engine's back buffer but kept three relics of the old offscreen design. Its depth-stencil view was panel-sized while the colour target was the screen-sized back buffer, and D3D11 silently drops a whole `OMSetRenderTargets` whose depth resource size differs from the render target's - the pass ran with no targets bound and every draw vanished. Its viewport was anchored at the screen origin instead of the panel rectangle, so any surviving geometry would have landed outside the window. And the dynamic-position scratch vertex buffer was declared and null-checked but never created, which skipped every streamed draw (head, morphed body) outright and zero-initialised the field nowhere. The depth buffer is now sized to the actual resource behind the back-buffer view (queried per frame, so an engine resize rebuilds it), the geometry draws through the panel rectangle as its viewport, and the scratch buffer is created on demand and grown to the largest streamed draw. The TGA content dumps that proved the fill and border reached the screen while not one character pixel existed stay in place.
- Fix the mesh-wide distortion (the "digital camouflage" on every skinned mesh, from faint on the head to gross on the body, arms and hair): vertex bone indices are LOCAL to their skin partition - index i means "the i-th entry of the partition's bone list", and only that list resolves to the global bone. The palette read them as global bone subscripts, so every partition bound its vertices to the wrong bones (a head partition with 2 of the skin's 46 bones fetched bones 0/1). Proven from a binary dump of the partition's GPU bytes: weights summed to 1, UVs were sane, the triangle list was whole-mesh indexed, and the only consistent reading of the indices was partition-local. The palette is now assembled by mapping each partition-local slot through `part.bones[]`, and the mesh weight validation is bounded by the partition's own bone count.
- Fix the digital-camouflage shading on hair, arms and clothing (second root cause): positionless FaceGen/morph partitions whose engine `vertexMap` was non-null were silently ignored whenever the partition's triangle indices happened to reference every one of the partition's vertices - the index-space heuristic treated that as proof of whole-mesh indexing and baked an identity copy of the morph data, so the partition-local vertex indices sampled the wrong source vertices and the whole mesh rendered as digital camouflage. The map IS the packing: a non-null `vertexMap` is now followed unconditionally, the index heuristic only sizes mapless partitions, and a packed partition whose indices still exceed its own vertex count is skipped rather than misread.
- Keep the world copy out of sight: the duplicated actor must exist in the world because the engine loads and submits its skinned 3D through the ordinary render path (a never-submitted skin carries a zero bone-matrix count and the panel would lose the whole body), but it no longer stands in front of the player - it is placed behind the view direction and the renderer culls it within ~0.2s of the first submission instead of ~2s. Fully removing the world copy needs a different 3D-lifecycle design and is recorded as a follow-up.
- Fix the ghost weapons, shield, bow and torch on the preview: the worn sync mirrored every inventory entry carrying a worn flag, and then (after the first fix) still mirrored the weapon-bearing mod biped slots - measured in game, the engine equips the bow on `kModBack`, one-handed weapons on the pelvis slots and the torch on `kModMisc1`, so the preview showed gear the player carried on the back or the belt. The mirrored slot list is now strictly the armour/clothing slots (body, head, hands, feet, hair, circlet, amulet, rings, neck/shoulder/arm/leg mod slots and face jewelry); weapons, shields, ammo, torches and back/belt-mounted gear never reach the preview.
- Fix the hair colour rendering as raw grayscale (the white-hair report): the engine dyes hair in its lighting shader by multiplying the texture's grayscale against the material's tint colour, a step the panel's own pixel shader did not reproduce. The material resolution now reads the engine's own hair-tint colour from the mesh's material (already the player's chosen dye) and the shader applies the same grayscale-times-tint product when a draw carries the hair-tint flag.
- Reproduce the FaceGen skin tone (the gray-noise skin and the black face report, after the palette fix had restored the geometry): the FaceGen material family (kFaceGen / kFaceGenRGBTint, measured on the CBBE body, feet and the head meshes) shades grayscale detail textures with the character's skin tone in the engine's lighting shader, so the panel sampled the raw gray maps and the skin read as noise on the body and near-black on the face. The material resolution now carries the preview NPC's skin tone (the QNAM body tint) for that material family, and the pixel shader maps the sampled luminance onto the tone the way the engine does - the tone modulated by the texture's shading detail, never clipped to white or black. The per-draw tint constant now packs the mode (none / hair dye / skin tone) in its fourth component.
- Port the engine's actual FaceGen RGB-tint shading (the skin camouflage, final root cause): Community Shaders' Lighting.hlsl reconstructs the engine's lighting PS exactly, and for `FACEGEN_RGB_TINT` (the CBBE body, feet and hands) the base colour is NOT a grayscale detail map times a tone - it is the texture's own RGB remapped by the quadratic `out = 1.0117 * (raw^2 + Tint * raw)`, with `Tint` the engine's lighting PS constant 23 (the NPC's tint; `TintColor`). The panel's earlier luminance-times-tone approximation treated the colour texture as a gray map and manufactured the high-frequency camouflage out of its own formula. The material resolution now resolves the tone from the NPC's kSkinTone tint layer (QNAM body tint as the fallback) and the pixel shader applies the CS quadratic verbatim for the tint family; the plain kFaceGen head path takes the same tone. The per-draw RenderDoc comparison (identical VS inputs, identical t0 texture, only sampler/rasterizer differences) ruled the vertex and binding paths out and pinned the difference to the pixel-stage colour math.

- Apply the material's own UV remap (the residual skin camouflage after the palette and skin-tone fixes): the engine's vertex shader maps raw UVs through `uv * scale + offset` before sampling (Community Shaders `Lighting.hlsl`, the `TexcoordOffset` constant), and atlassed materials - the CBBE body slots above all - carry non-trivial values, so sampling raw UVs read the wrong atlas regions tile by tile. The material's `texCoordOffset[0]`/`texCoordScale[0]` now travel in the per-draw constants and both vertex shaders apply the same remap; plain materials keep the identity.
- The per-mesh material census now reports the alpha property's testing and blending bits alongside the texture family and tint, so a hair or brow mesh whose white backdrop survives the composite is diagnosable from the log.
- Frame the whole body head to feet: the old automatic fit capped the framing radius so tightly that the head touched the window's top edge and the feet were cropped. The camera now targets the skeleton's true vertical span uncapped, sizes the framing radius from that span with headroom for the crown and soles, fits the distance against the panel's own tall aspect, and biases the framing centre slightly below the skeleton's middle so the figure sits centred instead of bottom-heavy; `CameraDistance` still overrides the fit.
