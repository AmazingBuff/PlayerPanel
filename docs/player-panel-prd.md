# PlayerPanel：独立角色摄影棚面板 PRD

版本：0.2  
日期：2026-09-28  
状态：产品目标与合成顺序确定；引擎接入及兼容性待验证。  
交付形式：基于 SKSE / CommonLibSSE-NG 的 Skyrim 插件。

本文件是 PlayerPanel 后续开发的产品需求基线。读者包括产品设计、插件实现与游戏内验证人员。文中“必须”描述验收要求，不代表现有代码已经实现。

本次确定从第一阶段直接验证世界画面与面板共存，不采用“背包期间用摄影棚替代世界画面，再改成双视图”的路线。工作区原有[独立角色面板 PRD](../../docs/independent-character-panel-prd.md)保留为历史参考；与本文件冲突的渲染路线和阶段安排以本文件为准。[Stage-0 记录](stage0-spike.md)属于早期试验材料，不构成本方案通过验证的证据。

## 1. 产品目标与术语

玩家在查看和更换装备时，能够在独立小窗口中观察完整角色及其展示动作，同时保留窗口之外的游戏世界画面。体验参考《博德之门 3》的角色面板，不假定或复制该游戏的内部实现。

| 术语 | 定义 |
| --- | --- |
| O | 游戏世界中的实际玩家角色，继续由原游戏逻辑管理。 |
| P | 面板内的独立展示角色，其外观来源于 O，其动作与展示状态独立。 |
| 摄影棚 | 仅包含 P、必要装备与展示背景的独立渲染场景，具有自己的相机、灯光和深度。 |
| 面板 | 摄影棚输出在游戏画面中占据的不透明矩形区域，不是额外的操作系统窗口。 |
| 共存 | 同一帧同时显示世界画面和角色面板；不要求两个场景在 GPU 上并行执行，也不要求菜单期间世界模拟继续运行。 |

核心要求：

1. **外观一致**：P 显示 O 当前的脸部、身体、服装、护甲和实际装备／持有的武器；不带入战斗血渍等无关临时污染。
2. **动作独立**：P 的姿态、动画进度、朝向和武器展示状态不必与 O 一致，面板操作不改变 O 的动作。
3. **渲染逻辑复用**：摄影棚尽量使用世界角色相同的材质与着色逻辑，使玩家安装的相关渲染修改能够作用于 P；摄影棚的相机、照明和背景独立。

“一致”不要求不同照明、视角和姿态下像素相同。“任意模组自动生效”是兼容方向，不是已有技术保证；实际支持范围必须有版本与效果级验证记录，不得以局部出图宣称全面兼容。

## 2. 确定的画面合成顺序

| 阶段 | 行为 | 输出与边界 |
| --- | --- | --- |
| 1. 世界画面 | 正常绘制游戏世界，完成该世界视图的游戏内后处理。 | 保留 O 与原场景，不移动主相机为 P 取景。 |
| 2. 角色面板 | 在独立摄影棚中绘制 P，完成必要的局部处理，再把结果作为不透明矩形合成到世界画面上。 | 仅覆盖面板区域，不与世界共用深度。 |
| 3. 其他 UI | 绘制背包内容、面板控件、提示框、光标及其他需要覆盖面板的游戏 UI。 | 保持正常交互与遮挡层级。 |
| 4. 最终后处理 | 在已合成的画面上执行 ReShade 等外部最终画面效果。 | 按此顺序，世界、面板及已绘制的 UI 均可能受影响。未安装时直接显示。 |

```text
世界 O → 世界渲染 → 世界视图后处理 ──────────────┐
                                                ↓
摄影棚 P → 独立渲染 → 必要局部处理 → 不透明矩形合成
                                                ↓
                                      其他 UI → 最终后处理 → 显示
```

这是产品要求的可见合成顺序。离屏准备工作可以在安全时点调度，但不得因此使用过期角色数据、破坏 UI 层级，或使摄影棚状态泄漏到世界绘制。

### 2.1 摄影棚的独立边界

- 使用独立相机、灯光、背景、颜色目标和深度目标；需要时提供自己的材质缓冲与历史状态。
- 摄影棚内部正确处理身体、装备的遮挡和透明材质。不透明窗口不等于关闭头发、薄纱和粒子的透明处理。
- 最终合成不提取角色透明轮廓，不计算 P 与世界物体之间的遮挡，不把 P 的深度写入世界深度。
- 世界天气、雾、附近物体和 O 的地理位置不决定摄影棚的构图与展示灯光。
- 窗口外的世界画面、主相机和下一帧渲染不得因摄影棚绘制产生异常。

### 2.2 后处理边界

- 世界视图的景深、受击模糊等不自动继承到摄影棚；摄影棚不重复执行完整世界后处理。
- 皮肤散射、材质合成等即使通过全屏 Pass 实现，仍可能是 P 正确着色的必要环节；不能仅因其“全屏”而省略。
- 摄影棚输出必须与合成目标的颜色表示一致。若输出为 HDR、目标已完成色调映射，应先完成匹配转换，避免发灰、过曝或重复色调映射。
- 最终调色、颗粒等读取颜色的效果可共同处理合成结果。依赖深度、法线、运动矢量或历史帧的外部效果，不会因颜色合成而自动理解摄影棚。
- 首版按普通 UI 面板定义外部深度效果的边界，不承诺向 ReShade 提供统一的双视图深度。由此产生的不兼容须在支持矩阵中明确，不得宣称该效果已完整支持。
- 游戏内后处理、第三方渲染框架与最终后处理按实际接入阶段分类，不按插件名称推断执行顺序。

## 3. 用户流程与交互

1. 在有效游戏会话中打开面板；原型使用热键入口，产品集成面向背包界面。
2. 准备 P 的外观和摄影棚资源，期间显示准备状态；窗口外保留世界画面。
3. P 以独立待机姿态显示。玩家可查看角色，并使用面板控件旋转展示方向或切换展示动作。
4. 背包装备操作仍由游戏处理。装备最终生效后，面板同步显示结果。
5. 关闭面板后恢复正常输入状态，停止不必要的摄影棚绘制和展示更新。

面板应适配背包留出的展示区域，并让文字、确认弹窗和光标显示在其上方。具体尺寸、按键、背包布局及原物品 3D 预览的安排在 UI 集成前确定；不预先固定某个 UI 模组。

## 4. 功能需求

### FR-01 外观与装备同步

- 打开时读取 O 当前生效的第三人称外观和装备；O 处于第一人称或未出现在主相机中，不应阻止完整展示。
- 同步范围包含脸部、肤色、体型、头发、持久外观覆盖、护甲和左右手装备；按支持清单覆盖种族、骨架与外观模组。
- P 的武器属于同一装备结果，但收放位置和姿态可按展示动作决定，不要求复制 O 的瞬时武器姿态。
- 以装备实际生效结果为准，不把鼠标高亮或尚未完成的装备请求当作最终外观。
- 连续换装时合并刷新，较早完成的加载结果不得覆盖较新的状态。允许暂时保留最后一个有效画面并提示更新。
- O 的 3D 重建后，P 应重新取得有效外观来源；不得跨读档持有失效节点作为有效数据。
- 不修改 O 的库存、装备或与其他角色共享的基础记录来完成预览。

### FR-02 临时污染过滤

- P 不同步 O 因战斗产生的血渍等已识别的临时 decal／污染效果。
- O 的原有血渍不因清理 P 而被删除。
- 妆容、纹身、角色设计中的疤痕等持久外观应保留，不能通过删除所有 Overlay 或相关材质来清理血渍。
- 对直接写入纹理、无法区分来源的第三方污染，不宣称已可通用剥离；须记录适配需求与实际限制。

### FR-03 独立动作与物理

- P 独立维护姿态、动画进度与根变换，至少支持稳定待机和一种可切换展示动作。
- O 攻击、蹲伏、游泳或转身时，不自动把相同姿态强加给 P。
- P 的动作切换、根运动及武器展示不改变 O，也不在世界中触发攻击、施法、碰撞或交互。
- 武器与装备附着于 P 的骨骼；动画切换和换装后不得残留错误附着。
- 若支持头发、衣物物理，其状态应独立于 O；具体物理模组以实测支持清单为准。

### FR-04 摄影棚渲染

- 按第 2 节顺序在世界画面上合成不透明面板，从首个原型开始保留两个视图。
- 使用可控的相机和灯光，默认保证完整角色及常见装备可见；首次不提供完整摄影棚编辑器。
- 尽量复用引擎角色装配、材质和绘制能力。通用材质替换、动态材质和角色专属效果分别验证。
- 必须正确处理所声明支持的蒙皮、透明裁剪、透明混合，以及必要的阴影／材质合成过程。
- 摄影棚使用自己的视图数据。不得依赖 O 在主画面可见、世界当前帧恰好绘制到某个角色 Pass 才能生成 P。
- 不得通过移动 O、切换主相机或覆盖整个世界画面实现面板。

### FR-05 暂停、UI 与输入

- 支持世界正常运行时的双视图验证，以及背包暂停世界时的 P 动画与必要换装刷新。
- 暂停时不通过额外推进世界模拟或 O 的动画来驱动 P。
- 只消费面板操作所需输入；关闭或失去焦点后不残留拖拽、按键、鼠标捕获状态。
- 原游戏装备操作、退出操作、确认弹窗和光标保持正常。

### FR-06 生命周期与失败处理

- 没有有效游戏会话、正在读档或返回主菜单时，不新建可用预览。
- 重复开关、换装、切场景、读档及渲染目标重建时，取消失效请求并安全重建所需资源。
- P 不成为可攻击、可搜刮或可交互的世界 NPC，不留下存档残留或可观察的游戏逻辑副作用。
- 预览失败时显示不可用状态并允许关闭；原游戏与背包仍可使用。
- 不静默退回显示 O、替换主世界画面或复制 O 的姿态，并将其算作需求完成。

## 5. 兼容性、范围与性能

### 5.1 兼容性验收原则

复用相同引擎接口不等于兼容所有插件。只针对 O 的身份判断、绑定固定渲染目标的效果、第三方内部状态，以及不同 Hook 链都可能需要适配。

| 类别 | 验证内容 |
| --- | --- |
| 游戏运行时 | 锁定 EXE、SKSE、Address Library 和 CommonLibSSE-NG 版本，分别记录结果。 |
| 原生渲染 | 完成材质、蒙皮、透明、摄影棚照明和合成基线。 |
| Community Shaders 等框架 | 按版本与功能记录 P 的材质、光照、局部处理是否正确；不能由原生基线外推。 |
| ENB 等其他路径 | 单独调查其接口和阶段，未验证前不宣称兼容。 |
| ReShade | 核实合成位于效果执行之前；区分颜色效果与依赖深度的效果。 |
| 外观／动画／物理模组 | 分别验证形变、覆盖纹理、附加节点、独立动画和物理更新。 |

支持矩阵至少记录：版本组合、测试角色／装备、效果开关、结果、已知限制和验证证据。候选基线为本地前期记录中的 Skyrim 1.6.1170 与 SKSE 2.2.6，实施前重新核实；不将其当作本次已验证状态。

### 5.2 首版边界

- 先针对单一非 VR 运行时和普通人形玩家形成可验证基线；新增运行时、变身或特殊骨架须另行验证。
- 独立 Actor 是优先调查的承载方式，但不是本 PRD 已验证的实现契约；其他方案必须满足相同的外观、动画与隔离要求。
- 不包含试穿、幻化、外观编辑、完整库存复制、随从面板、多角色同屏、摄影导出和通用双视图后处理框架。
- 未支持的变身或角色形态显示明确状态，不用默认人形冒充当前角色。

### 5.3 性能与稳定性

- 关闭面板后停止摄影棚绘制与不必要的展示更新，不进行持续 GPU 读回。
- 面板开启时按窗口需要选择输出尺寸，不默认再渲染一份全屏世界。
- 验证时记录开启前后的 CPU／GPU 帧耗时、显存占用，以及打开和换装延迟；反复开关后不持续累积资源。
- 首个双视图原型测量基线后，在功能扩展前确定量化预算。未测量前不填写虚构的帧率或毫秒承诺。

## 6. 验证与交付阶段

| 阶段 | 交付与通过条件 |
| --- | --- |
| M0：双视图渲染验证 | 从开始就同时显示世界与摄影棚；在其他 UI 之前合成不透明窗口；验证 P 着色及世界下一帧不被污染。可先固定姿态，但必须使用独立展示实例。 |
| M1：外观与动作闭环 | 同步支持范围内的外观和装备，过滤临时血渍；P 独立播放与切换展示动作，O 不受影响。 |
| M2：暂停与背包集成 | 暂停时 P 可更新，背包换装正确同步，输入与 UI 层级正确，关闭及读档清理完整。 |
| M3：目标环境兼容与性能 | 在明确版本组合上验证渲染框架、最终后处理及外观扩展，提交支持矩阵和性能结果。高风险兼容性可在 M0 提前验证。 |

M0 的通过证据必须是可重复的双视图画面与状态隔离结果。单个 Pass 离屏出图、截图或世界内可见分身，不足以通过。技术路线失败时返回设计评估，不以违反核心要求的替代效果交付。

### 验收场景

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| A01 | 正常世界画面中打开面板并移动主相机 | 窗口外世界正常，摄影棚构图独立，P 不受世界遮挡。 |
| A02 | 第一／第三人称分别打开面板 | 均显示完整第三人称角色，不要求 O 在主画面中可见。 |
| A03 | O 蹲伏或攻击，切换 P 动作 | 两者动画独立，P 的动作不产生世界行为。 |
| A04 | O 带有战斗血渍和持久纹身 | P 不带支持范围内的临时血渍，保留纹身；O 的血渍不变。 |
| A05 | 连续换装并改变左右手武器组合 | P 最终匹配最新生效装备，旧加载结果不覆盖新结果。 |
| A06 | 使用透明头发、蒙皮装备和目标材质 | 内部遮挡、透明与着色正确，窗口背景仍不透明。 |
| A07 | 打开暂停背包，换装并切换展示动作 | 世界保持暂停，P 完成必要更新，游戏装备与 UI 操作正常。 |
| A08 | 在面板上方显示提示框和光标 | UI 层级正确，不被摄影棚绘制覆盖。 |
| A09 | 开关目标 ReShade 颜色效果 | 在约定组合中，世界、面板和 UI 一起按该效果处理；深度效果单独记录。 |
| A10 | 切换目标渲染框架的待测功能 | 逐项确认 P 的表现，并检查世界当帧和下一帧没有状态污染。 |
| A11 | 反复开关、读档、返回主菜单、改变输出尺寸 | 无崩溃、失效引用、输入残留和持续资源增长。 |
| A12 | 外观加载失败或角色形态不受支持 | 显示可理解的状态，保留游戏正常操作，不冒充成功。 |

## 7. 实施前需关闭的技术问题

下列问题属于实施设计与实验，不改变本文件的产品顺序和核心要求：

1. P 的创建、模型准备、更新和销毁方式，以及外观数据和可变资源的所有权。
2. 世界后处理完成、其他 UI 绘制开始之间的实际合成接入点，以及与已有 Hook 链的协作方式。
3. 摄影棚需要哪些材质与局部处理阶段；引擎和目标框架的哪些状态必须隔离与恢复。
4. 暂停时 P 的动画、模型刷新及支持范围内物理更新的入口。
5. 首批外观／渲染框架版本、支持效果、背包 UI、动作资源及性能预算。

CommonLibSSE-NG 暴露的菜单场景、相机、动画和渲染提交接口可作为调查入口，但不等于已经存在可重入的完整第二视图 API。现有重放试验只提供局部证据，不据此锁定正式实现。
