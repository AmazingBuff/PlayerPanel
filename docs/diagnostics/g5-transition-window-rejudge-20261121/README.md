# 过渡窗重判：G4P-7 的超差拆分（2026-11-21，纯离线）

**结论：装备段过渡窗（candidate `completed ≤ 12`）承载了全部 scale 超差（352 → 0），并占平移超差的 21.3%、旋转超差的 5.7%；剩余部分不是过渡造成的——平移超差在窗外的 236 对里几乎全部落在同一批轨道上（`track45`、`track60–66`，每对都超），是**静态附件偏移**而非时序问题。** `G4P-7` 维持 **FAIL**，但失败被拆成两个可分别处置的成分。

## 五、裁定与影响

1. `G4P-7` 维持 **FAIL**：丢弃过渡窗后 `tau_p` 仍有 3,012、`tau_r` 仍有 15,805，远超接受线。
2. 失败可以拆成两个独立成分，各自需要独立预注册：
   - **A：过渡混合窗**（装备 `completed 1–12`，≈0.2 s）。它贡献 100% 的 scale 超差、21% 的平移、6% 的旋转。处置方式只有两种：把窗口排除在配对之外，或在配对里显式建模混合权重（v120 run 1 已测出 `w = k/11`）。
   - **B：静态附件/内部状态偏移**。窗外的平移超差几乎全部落在 `track45` 与 `track60–66`，每对都超、幅度恒定——这是 v105 归因里那 5 根静态附件轴的直接证据，不能用任何时间对齐或更宽容差解决。
3. 旋转轴（15,805）另需单独分解：它既不在过渡窗里，也不集中在少数轨道上（本重判未做逐轨排名，下一轮可复用同一脚本加一列）。

## 六、复现与边界

- 只用仓库内归档工件；不产生新的游戏数据，不改变任何 `tau_*`、不改变正式批次记录。
- 逐轨排名与 P99 采用本脚本实现（最近秩法），与 `tools/gate4_pair.py` 的分布函数有 <1% 差异，不用于改写正式数值。
- 过渡窗宽度 12 来自 v120 run 1 实测的 `1/11` 权重步进（0.2 s ≈ 12 帧）；本轮未对源侧做同语义取证。
