## 三、裁定

**按契约 §三 的预注册规则：**

> 若 CW-P2 采到 `801` **常驻** → **世界与面板行为一致，"卡 Start"不是面板缺陷**，而是 Smooth Moveset 的相位设计在两种场景下相同。此时 C-IDLE 的修复方向应关闭（选项 C），缺陷降级为"上游资源配置特征"。

**判定：CW-P2 命中"常驻"分支。**

### 3.1 这意味着什么

1. **`mag_start on`(801) 在正常游玩中同样不被清除**，与 [v127 面板会话](../idle-loop-v127-session-20261124/README.md) 的 20/20 快照一致。
2. **`801` 与 `802` 并存时 OAR 的行为在世界与面板里应当相同**——因为两者的输入条件一致（`HasMagicEffect` 分别问 801 与 802，两者都命中）。
3. 用户在游戏中观察到的"面板内卡在 Loop Start、世界内正常转 Loop"，**不能用标记差异解释**（标记状态相同）。

### 3.2 仍未解释的

- **世界与面板在 `both` 状态下的 OAR 选择结果不同**（世界转 Loop、面板选 Start）这一点，本探针**没有**测量 OAR 的选择结果，只测了标记。因此不能从这个结果推断"面板行为正确"。
- 但可以确定：**不是"面板缺了清 801 的机制"**——世界也没有清。

### 3.3 对 C-IDLE 修复方向的影响

| 方向 | 裁定 |
| --- | --- |
| **B（补派 `sp_start off`）** | **否决**。世界不靠清 801 来离开 Start，补清会创造世界不存在的状态。 |
| **A（面板侧强制驻留）** | 仍是候选，但依据从"弥补缺失步骤"变为"修正 OAR 在面板上下文的判定差异"，需要先解释差异来源。 |
| **C（记录为限制）** | 依据增强：缺陷不是面板偏离世界协议，而是两者在 `both` 状态下的选择分歧。 |

## 四、探针实现缺陷与修正

首轮部署的探针在判读时发现解析 bug：用 `value & 0xFFFFFF == 0x801` 比较，而运行时 token 是六位（`243801`），导致所有行报 `start-on=false`。

**修正**：改为比较低三位十六进制（`value & 0xFFF`）。修正后重算同一份日志得 §2.1 的分布。

**无需重跑**：探针原始输出保留完整 `markers='…'` 字符串，修正规则可离线套用到既有采集。修正提交 `34d099e`。
