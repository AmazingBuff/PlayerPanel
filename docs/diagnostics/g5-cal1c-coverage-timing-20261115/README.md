# C-G5-CAL1-C 覆盖与时间审计（2026-11-15）

**状态：审计完成。裁定：CAL1-B 不能覆盖门 4 的 116/116；`epsilon_t` 不能由现有 CGRD 单独产生。需要两个预注册修订；本轮不产生新 `tau_*`/`epsilon_t`。**

本审计回答 CAL1-B 之后剩余的两个门 4 冻结问题：

1. 控制 B 只有 99 条 transform 轨，门 4 的 116 轨分母中另外 17 条是什么，能否用 CAL1-B 的 tau 覆盖？
2. 现有三进程 CGRD 的 TSC 数据能否补出 `epsilon_t`，还是需要新的时间模型/仪器？

## 二、TSC 频率与 `epsilon_t`

### 2.1 本机 TSC 探针

本地 gitignored 探针（`build/tsc-probe`，CPUID + `__rdtsc` + QPC，3×1 s）：

| 项 | 值 |
| --- | --- |
| invariant TSC | **1**（CPUID 0x80000007 EDX bit 8） |
| QPC frequency | 10,000,000 Hz |
| TSC 频率（3 次） | 4,291,863,648 / 4,291,864,114 / 4,291,863,499 Hz |
| median | **4,291,863,648 Hz**（约 4.291864 GHz） |
| min/max 相对跨度 | 约 1.4e-7 |
| 三份归档 CGRD 日志斜率交叉核对 | 约 4.285–4.291 GHz（<0.2%） |

探针输出：[tsc_probe.txt](tsc_probe.txt)（SHA-256 `50544EFC14D1E5070FDA9F490D8FFEDEF1561EC7945E16C1130681F016DE479E`）；探针源码 SHA-256 `4A01F6D8AAA93DA2DDD631A6A1C2DD5444A8B8232F7088DA6C5899C9877057E6`（仅在本地 build，不进仓库/插件）。

### 2.2 读取区间不是 `dt_clock` 阈值

用中位频率把三份 CGRD 的 `tsc_after_compare - tsc_call_start` 换算为秒：

| run | 最大读取区间（cycles） | 最大区间（µs） | 最小区间（µs） |
| --- | ---: | ---: | ---: |
| 1 | 162,196 | 37.79 | 10.16 |
| 2 | 102,469 | 23.88 | 9.90 |
| 3 | 268,790 | **62.63** | 10.14 |

而门 4 dry-run 的 `dt_clock` 分布是 median 4.7 ms、p95 11 ms、max 17.8 ms。**若把 `epsilon_t` 直接定义为读取区间（约 63 µs），`dt_exclude` 会排除全部配对。** 因此 `epsilon_t` 不是“TSC 频率换算”一件事，必须区分：

| 分量 | 含义 | 现有材料 |
| --- | --- | --- |
| `epsilon_read` | TSC 表示（1/f）+ 控制读取/采样区间上界 | 可由归档 CGRD + 本机 TSC 频率给出（约 63 µs 上界） |
| `epsilon_phase` / `epsilon_grid` | 配对相位/预定网格的时间归属与 clip 时间量化 | 需预注册定义；候选过渡 clip 有阶梯/滞后形态（门 4 §15.3） |
| `epsilon_t` | 门 4 判据使用的时间等价界 | 必须由上述分量按预注册规则合成；不能直接等于 `epsilon_read` |
| `Δt_clock` 处置 | 源/候选相位差是否/如何影响配对有效性 | 独立槽位；不得用姿态容差吸收 |

### 2.3 归档运行的频率登记缺口

CAL2 §五.4 要求 TSC 频率/单位与单调基准**随进程登记**；v104 CGRD/日志没有该字段。现有三份归档只有原始 cycles 与 C2-F 的单调性证明。可选路径：

| 路径 | 内容 | 边界 |
| --- | --- | --- |
| **T1（推荐先评审）** | 机器级 invariant TSC 标定 + 归档三进程的 TSC 单调性，登记频率/不确定度与“非逐进程字段”披露 | 需 CAL1-C 时间附录；只适用于同机、invariant TSC、归档 v104 批次 |
| T2 | 新 v105 仪器在进程启动/关闭记录 TSC 频率/单位/单调基准；重采三进程 | 代码/构建/部署/上机；最严格但成本高 |
| T3 | 直接用日志毫秒斜率当频率 | 只有约 0.1–0.2% 一致性，不能作正式登记；仅作旁证 |

## 三、裁定与建议

1. **门 4 116/116 当前不成立**：17 条 item/wing/Belly 轨没有 CAL1-B 控制；需要 `C-G5-G4-COV v1` 覆盖修订（推荐 99 主分母 + 17 辅助账本）或另建控制。
2. **`epsilon_t` 当前不能填**：TSC 频率可标定，但 `epsilon_read` ≠ `epsilon_t`；必须先预注册 `C-G5-TIME v1`（或 CAL1-C 时间附录），定义 `epsilon_read`、`epsilon_phase/grid`、`epsilon_t` 与 `Δt_clock` 的合成/处置。
3. **不产生新数值**：本轮没有新 `tau_*`/`epsilon_t`；门 4 仍只有 CAL1-B 的限定姿态槽位，未完整冻结；门 5 未授权。

**待用户批准**：是否按方案 A 起草 `C-G5-G4-COV v1`，并按 T1 起草 `C-G5-TIME v1`？两项都属于门 4 协议修订，须在正式门 5 采集前冻结。
