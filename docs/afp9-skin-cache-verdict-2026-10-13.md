## 2. 根因：`NiSkinInstance::frameID` 是"本渲染帧已算过"的门

坏帧与好帧的普查行完全同构，唯一区别在**蒙皮矩阵是被谁、什么时候算的**：

```
R01 census frame=8041 render-frame=23188 geoms=16 skinned=12 passes=16
           first='3BA' skin-frameID=23188 num-matrices=49
           bone0='NPC UpperarmTwist1' bone0-world-t=(-4.6,-486.1,16.7)   ← 骨骼在锚点
```

CLib 结构（`RE/N/NiSkinInstance.h`）：`boneWorldTransforms` 是**指向各骨骼 world 的指针数组**（实时）、`frameID` 是引擎"本渲染帧已计算"的标记（`numMatrices`/`boneMatrices` 是它的产物）。若该 id 已被**取景写入之前**的某次更新置为当前渲染帧，`SetupGeometry` 会保留旧矩阵：**蒙皮身体按旧骨骼世界（泊位，-8000）绘制 → 看不见**；而斧头是刚体、直接吃节点世界 → **照常可见**。这解释了"同一会话内完整人物与孤斧交替"，也解释了此前所有"只有斧头对"的现象。

## 3. 修复（AFP9i）

提交批次前把该子树所有 skin 的 `frameID` 置为无效值（`invalidate_skin_cache`），让引擎**自己**按本帧写入的骨骼世界重算：

- **不写 `boneMatrices`**——缓存全程归引擎所有（维护文档不变量 1 未被触碰），我们只让它的"已完成"标记失效；
- 顺带解决姿态延迟：AFP 写入的姿态现在能在**同一帧**反映到蒙皮，而不是下一帧。
