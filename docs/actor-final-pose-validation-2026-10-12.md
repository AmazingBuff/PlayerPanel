# 同一 Actor：最终姿态应用与直接绘制测试单

日期：2026-10-12。依据：[PRD 0.9 §6.6](player-panel-prd.md)。

**待实现、待测试。**当前 HKX44 是傀儡取 clip 后驱动复制图的构建，不能执行本单的新路线。以下动作名是测试包需提供的控制行为，具体键位由 manifest 指定，不能推定现有 F2／F7／F8 已支持。

## 1. 本轮最小问题与范围

不修改 OAR，保留克隆 Actor P 与其第三人称 3D 的绑定，暂停时推进它的行为图，取得最终姿态并手动应用到它自己的骨架，然后直接绘制这套网格，是否能持续显示正确动画？

第一轮只做 R00–R04，SMP／CBPC 关闭。不摘图、不清空 data3D、不 Disable／SetDelete 后继续用图、不重置 T-pose，不选最强 clip 再采样到另一套骨架。经验轨道求解器及程序化 fallback 全部关闭；输出不可用时明确阻断，不能假装路线成功。

## 4. 游戏内验证

### R01：同一 Actor 的静态直绘

1. 使用独立测试存档进入正常游戏，等待 P 的模型、脸部和装备准备完毕；记录装配完成依据，不仅按等待秒数推定。
2. 打开暂停背包。核对 P 的 actor ID、`Get3D(false)` 根、graph 绑定与当前 generation；日志证明实际绘制来自这个根。
3. 推图、手动姿态应用和物理均关闭，显示 P。检查身体、脸、头发、护甲和左右手装备，保存正／侧／背面截图。
4. 改变相机取景和观察方向，确认 Actor 位置／模拟尺度、根宿主不变。不能复用旧 snapshot `pose()` 搬移整图后把结果计为直绘。
5. 关闭背包观察世界隐藏情况，检查克隆闪现、可交互分身、落地／AI 动作、原角色位移或外观改变。

**通过**：显示网格确属同一 P，Actor 始终持有其 3D，支持范围内外观正确，世界无可观察副作用。静态出图不代表更新或物理成立。
失败查实际 graph／geometry 归属、装配／skin 初始化、fade 与 render target；不恢复摘图或 Disable 作为“同 Actor 已通过”。

### R02：确认最终输出确实更新

1. 在暂停背包中保持姿态应用关闭，记录 A0、A1 和节点姿态，建立 3 秒静态基线。
2. 开启推图，观察 5 秒。日志应分别显示图的 update 时间、实际最终输出内容变化及节点变化；不以 clip localTime 单独判成功。
3. 选择有可观察肢体变化的已知 idle；至少保存三个不同相位的输出。若所选 idle 变化过小，换已声明夹具并重新建立基线。
4. 冻结全部 3 秒，执行两次单步，再继续。核对冻结不推进、每次单步恰好更新一次。
5. 核对元素数量与骨表、当前 graph 与 3D generation、有限值、缩放和数据来源。仅 39 个名字可达不能算完整骨架输出。

**通过**：确定的最终输出在自有时间上演化、覆盖所声明显示样本所需的动画骨，控制语义正确。
若图时间变化而输出不变，定位求值阶段、输出缓冲或应用层；如果输出有效但节点不变，属于 R04 要补齐的阶段，不判路线失败。
若应用关闭时节点也自然更新，如实记录该运行时已有自动应用，不人为压制它以制造手动应用需求。

### R03：用引擎自然应用建立独立参考

1. 在未暂停、P 由引擎正常推进的阶段，对一个已知动作的多个相位进行只读采样。插件不能同时额外 tick 行为图。
2. 在实现端已经确认的时点，保存同一更新对应的最终图输出及引擎应用后的节点 local／world。读数无法确认同帧／同状态时标记无效，不据此判断映射。
3. 根据拟议手动应用规则在临时数据中预测节点姿态，**不写回正常运行的 P**；与第二步的引擎实际节点逐骨比较。
4. 平移、旋转、缩放分别统计；列明姿态输出到 NIF 的对应、CME／helper、根运动、缺失／跳过骨和目标网格有效权重。
5. 首轮物理关闭。IK／控制器等若位于输出之后，记录真实执行阶段与比较对象；不能让两侧一边含后处理、一边不含，再用放宽阈值消差。

**通过**：对声明骨域的多相位独立比较符合 manifest 容差，目标网格必要骨均有可靠处理。
骨名命中、索引同数量、矩阵可读和写后读回均不足以通过。若暂时只能覆盖核心骨，仅记部分机制成立；额外骨影响头发／护甲等时不能外推全角色正确。

### R04：暂停时手动应用与画面随动

前置 R01–R03 成立；若正常参考尚未取得，受控节点写入只作前置诊断，不计最终姿态正确通过。

1. A：暂停背包、物理关闭，推图开启但应用关闭，观察 5 秒，保存 A0–A5。记录“输出变化／节点保持／画面保持”或实际自动应用状态。
2. B：同一 P、装备、相机和时间规则，开启手动应用，观察至少三个非等价相位；记录最终输出、应用后节点、pass 前节点和相位画面。
3. 这两段是阶段因果对照，不能把不同相位的 A/B 直接逐像素相减。数值正确性沿用 R03；如需同相位配对，使用安全持有的深复制输出测试节点应用，不盲目 rewind 活行为图。
4. 冻结全部、单步两次、继续，再关闭手动应用。观察冻结保持、每单步产生对应姿态，以及应用关闭不跳回 T-pose。
5. 核对 renderer 没有再恢复 snapshot world／绑定姿态，没有旧 clip 重放参与；蒙皮由实际 actor 节点准备，CPU 缓存不手写。

**通过**：B 从最终图输出到节点、蒙皮和画面形成稳定链路，A4 保留 A2 的姿态，阶段控制正确。
输出变而 A2 不变查映射／空间；A2 变而 A4 恢复查覆盖；A4 正确而画面不变查真实 draw、skin 权重与引擎蒙皮准备。不要重新猜未知缓存槽位。

### R05：OAR、混合与一次性动作

1. 使用已知会触发替换的 OAR 配置，保存实际资源身份及条件。P 的身份是克隆 Actor，不假定所有玩家专属条件都成立。
2. 在暂停背包中运行 idle→装备动作→持械 idle，至少观察单手与另一已支持武器族；录制整个切换窗口，不仅等过渡结束再截图。
3. 记录活动集、权重和最终输出，至少取过渡开始／中间／结束三个样本。显示输入必须仍是最终图输出，不能因为某个 clip 权重最大就改用它单独采样。
4. 核对换装动作实际播放次数、回到 idle 的时间、替换／重选是否发生于暂停内、节点连续性及是否出现跳回开头。
5. 若行为图本身持续重入或替换件配置为 looping，区分图／配置语义与显示应用错误，不直接按文件名强制截断冒充最终输出。

**通过**：OAR 在声明条件范围内对 P 决策，显示保留最终混合与过渡，动作时序符合预先约定。这里只证明 P 条件下的选择，不保证 P 与 O 选择相同替换件。
失败分为图决策、最终输出可达性、映射／应用或显示覆盖，不能把所有错位归因于轨道重排。

### R06：外观换装与 3D 重建

1. 在已确认安全的线程与装配流程中，通过正常背包装备操作更换右手武器一次，再更换护甲一次；只读 O 的最终装备结果后装配 P。
2. 分别记录 Actor ID、旧／新 root、graph／骨表／3D generation、装备请求／提交代次、节点与网格清单。
3. root／骨表改变时立即停止使用旧映射和旧姿态数据；重新绑定后才恢复应用与 draw。等待装配完成，不将临时缺失节点当作有效替代。
4. 检查脸、体型、护甲、双手装备、武器附着与动画状态。仅出现新动作族不能算全部换装成功。
5. 旧树注销／渲染引用和任务屏障已有安全证据后，再测连续 A→B→C，最终只能提交 C；未满足时本子项填阻断。

**通过**：外观和图属于同一个 Actor，旧树不再写入，最新装备生效，续接／重置遵守声明规则。
若换树生命周期尚不明确，先停留在不更换根的受限样本；不要通过无限停放旧树执行压力测试。

### R07：来源隔离、时间与世界关联

1. 在无装备操作的暂停窗口记录 O 的骨架／引擎姿态和附近 NPC 的参照／根状态基线；执行 R04 的开关、单步和取景序列后再对照。
2. 只排除确实归插件所有的 P 身份，不能通过白名单排除 O 或来源图。声明 NPC 观测覆盖；未采全骨／物理状态就不报告全面冻结。
3. 对 P 检查碰撞、激活、战斗／施法、AI、世界可见性和原位置的可观察变化。固定运动类型不等于所有世界副作用已经排除。
4. 30／60／120 FPS 上限分别验证累计图时间与单步；核对每渲染帧只调度一次，不因多个 pass 更新多次。未达到目标 FPS 如实记未覆盖。
5. 切出游戏 3 秒再恢复，按 manifest 验证补步上限和焦点策略；再关闭／重新打开背包，检查时钟不追赶隐藏期间的全部时间。
6. 相机旋转和缩放取景，核对模拟坐标、骨架尺度和 OAR 条件不被取景操作意外改变；临时渲染变换必须有恢复与 worker 隔离证据。

**通过**：世界维持原暂停规则，O／受监视 NPC 无额外推进，P 世界副作用在声明范围内受控，图时间与取景规则正确。
装备装配造成的合法来源变化单独记录并重新建立静态基线；不能用重新基线隐藏无装备操作期间的漂移。

### R08：SMP／CBPC 在同 Actor 上生效

1. 先核对两套后端实际注册的是 P 的当前 3D，而非 O 或旧树。记录 Actor 筛选、节点／网格、配置、系统／任务身份与 generation。
2. 先只开 SMP，再只开 CBPC，最后按明确骨骼职责组合；复用 [V03–V08](s3-independent-physics-validation-2026-10-10.md) 的不步进／步进、冻结动画、碰撞和时间对照。
3. 世界保持暂停，只有 P 的物理按显式 dt 推进。冻结图输出后保留物理时间，检查惯性响应；冻结全部后两者停止。
4. 检查 A2→A3→A4：物理输出在 pass 前未被最终动画再次覆盖；两个后端不争写同一个输出骨。
5. 加入来源物理状态观测后再宣称物理隔离通过；NPC 根不动不能证明全部动态骨不动。

**通过**：实际求解器响应与碰撞成立，仅 P 更新，更新顺序和覆盖正确。
没有定向推进入口时填阻断并继续调查；不能调用全局 step 或解除主模拟暂停来完成本项。Actor 可识别不代表无需适配。

### R09：停止、销毁与会话边界

1. 提出停止请求：停止图／姿态应用／物理调度，等待相应任务和 draw 完成，确认旧 generation 不再被消费。
2. 按已调查的引擎合法顺序解除后端和插件引用，处理装备、Actor 与动态复制基础记录的所有权；记录资源实际释放，不能仅置空 `m_puppet`。
3. 基础销毁成立后，再测完整开关 5 次；记录预热基线、实际 Actor／图／系统／动态记录数量与资源变化，检查是否收敛。
4. 分别测试读档、返回主菜单和经主菜单读档。旧 actor ID／任务／请求全部失效；新 P 不能被旧映射或旧回调写入。
5. 保存／加载前后检查预览残留。运行时 formID、`released` 行或新 `born` 只能证明部分边界行为，不证明旧对象回收或无存档残留。

**通过**：实际回收、无失效任务／引用、会话隔离与资源收敛同时成立。未有基础释放证据前，不执行重复创建、读档或连续换树压力测试；一份 Actor 短测后结束进程，回收项填未测试。
