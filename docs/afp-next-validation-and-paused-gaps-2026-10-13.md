# AFP 后续验证：覆盖、直绘、物理、表情与身体变形

日期：2026-10-13。依据：[PRD 0.10 §6.6](player-panel-prd.md)。

本文件补充 [同 Actor R00–R09 测试单](actor-final-pose-validation-2026-10-12.md)，不是新 DLL 的使用说明。
下列诊断控制与新采样尚需实现和发包；具体键位写入 manifest，不恢复本机冲突的 F3。当前 AFP8 使用 F2 标记、F4 驱动循环。

## 1. 新增用户观察与正确结论

用户观察：暂停时当前 clone 的动作可应用，但没有物理效果，脸部表情变形也不生效；另补充克隆 Actor 未应用原始 Actor 的身体变形。
本次未附构建哈希、动作／装备、表情输入或独立日志，因此记录为用户画面观察，不强行归入 AFP8 的某个 mark。
当前 renderer 仍调用复制图的 draw；尚未直绘傀儡本身，不能因为名字叫 clone 就判断屏幕使用哪个 Actor／头部。

已知代码与日志能说明更新和同步缺口，但尚未定位所有版本／身体上的唯一运行时断点：

| 链路 | 当前证据 | 能推出什么 |
| --- | --- | --- |
| 骨骼动作 | 姿态写入节点，绘制时蒙皮；AFP 有最终输出／同 Actor 节点应用结果 | 可说明身体运动成立，不能外推物理或脸部通道 |
| 指定物理 | AFP8 `cbpc=not-registered smp=not-registered`，A3 `physics=skipped` | 独立显示物理尚未接入，本轮无物理符合明确测试范围；不否定后续能力 |
| FaceGen | 当前姿态应用只写 local 并重算 world；复制图主动去掉控制器／userData，没有面部状态同步或独立 FaceGen 更新流程 | 骨骼写入未覆盖表情链；具体是输入、权重求值、morph、上传还是头部目标错误，需 F00–F04 |
| 身体变形 | 用户观察克隆 Actor 与 O 的体型不一致；当前 Actor 创建只显式复制基础记录，没有运行时身体 morph 同步步骤 | FR-01／R01 的完整外观未通过；按 BM00–BM03 区分体重、模型、实例变形及骨缩放，不锁定某个模组为根因 |

## 2. 四项先行建议

### 覆盖：不要将观察匹配数当写入数

AFP8 在世界参考中标定 98 槽，暂停输出有 116 槽；应用用 `min(m_targets.size(), count)`，98 槽中 written=92、unreachable=6。
新增 18 槽未进入循环。之后的 109/109 是观测节点符合输出，不是插件写满 109 根的证据。

下一包需要：

1. 按已确认的完整骨表建立绑定身份，不用某次较短姿态数组长度代表全部骨架。3D／graph／骨表代次变化时重新绑定。
2. 同一帧记录 `output-slots / mapping-slots / attempted / written / missing / intentionally-skipped / unprocessed`，各集合互斥且能对账。
3. 点名新增 18 槽、6 个不可达项：索引、骨名、父链、名字歧义、skin／palette 必要性、跳过原因；不能全归为 helper。
4. 对五个武器附着 world 超差节点，检查武器实际附着、helper 坐标和手部／收放状态。相应武器可见时做截图与数值对照，不能仅因图未驱动就无条件排除。
5. 正常参考先核对旋转，再分别核对平移／缩放与后处理范围；阈值提前声明，不靠 90% 旋转比例证明所有必要骨正确。

### 直绘：接通实际 A4／A5

1. 使用 P 实际 `Get3D(false)` 根，复用 `draw_figure_passes`，禁用该画面上的旧复制驱动。日志证明实际 pass geometry／skin 属于 P。
2. 同帧在 A2 应用后、A4 pass 前、A5 draw 后采样相同骨与头部／装备；保存三个不同相位画面。
3. 若用临时取景变换，列出改写的 root／节点 local、world、previousWorld、包围盒和渲染状态，建立恢复前／后对照；任务屏障须防止动画／物理读取展示空间。
4. 检查关闭／失败出口也恢复，下一世界帧无泄漏。累加器相机字段为空只否定该已调查字段可直接使用，不证明所有相机适配路径都不存在。
5. 首轮仍关闭物理及独立脸部更新；看见身体动画只通过直绘前置，后两者分别测。

### 缓冲与混合：第一个非空不等于最终显示缓冲

现行 `live_pose()` 返回第一个可读且有元素的输出；AFP5 两槽都有数据，插值字段非零，但这不证明各字段含义或应用规则已完整验证。

下一包对 idle→equip→idle 整个过渡记录两个输出的有效标志、元素数、内容摘要、graph 相关插值状态、update／生成序号与实际应用源。
先在正常引擎更新中确认当前／历史输出及插值语义，再在暂停中执行同样规则；分别测试单槽与双槽有效、两个缓存地址变化、冻结／继续。
不以两字段非零直接认定它们就是可相加归一的权重，不盲目线性混合四元数。
一次性动作重入要先区分行为图／OAR 配置与显示应用，不重新引入按最强 clip 采样的回绕修补。

### 回收与压力

R09 仍是重复开关、连续换树／刷新压力测试前置。仅清引用或停放旧图不能宣称回收。
当前只安排一份 Actor／图短测与明确同步的单次装配；解除旧渲染／FaceGen／物理引用后再销毁图。

## 3. 为什么动作有了，物理仍没有

动画指定一帧骨架姿态；CBPC／SMP 维护自己的速度、约束、碰撞与历史状态，以时间步求解，再覆盖其负责的节点／几何。
这两者不是同一个计算。`unk2A` 的本轮证据是强制行为图生成，不是强制更新所有插件或 Actor 子系统。

复制图保存了当时的外观／物理形状，没有获得源角色的模拟实例。去掉 `collisionObject` 也不能单独作为 SMP 注册不存在的证明：SMP 的 Bullet 系统与节点 collisionObject 是不同入口。
公开 CBPC 源码按 Actor 的加载骨架绑定；复制图没有对应 Actor 身份／更新链时不能直接调用源 Actor 的接口来更新它。
已调查 FSMP 主循环在游戏暂停时 suspend，因此即便后续 P 已注册，暂停时也不自动进行独立模拟。
未修改 DLL 的公开接口能否完成定向更新仍需按安装版本核对，不能直接呼叫全局 step 让整个世界恢复。

**物理上机行为（R08，细节复用 V03–V08）**：

1. 列出当前显示根及后端绑定根、actor ID、系统／节点／配置、dt／累计时间；如果根不是同一份，本轮先阻断。
2. 选择正常游戏已确认有效的一个 SMP 装备和一个 CBPC 输出骨；分别只开一个后端，做同输入下不步进／步进对照。
3. 冻结基础动画 5 秒、保持物理时钟；检查惯性与声明配置的衰减，再冻结全部，检查双方停止。
4. 同路径碰撞开／关，记录有效接触而非只看摆动。A3 的结果必须保留到 A4／A5，不能被骨架恢复抹掉。
5. O／NPC 的实际动态状态保持暂停基线，不能仅用 NPC 位置不动替代物理隔离。定向入口未实现记阻断，不修改全局暂停。

## 4. 为什么脸部表情不会随骨骼姿态自动生效

Skyrim FaceGen 的 expression、modifier、phoneme 和 custom 权重、眨眼状态，与身体骨架的 hkQsTransform 输出是不同数据。
面部常规表情需要相应形变资源和更新／提交路径；头部节点的旋转可以让脸转向，不等于嘴角、眉毛或眼睑已经形变。
部分模组使用额外面部骨，必须按实际模型分类；这类样本还需检查上述覆盖缺口，不能把所有脸部变化都归为 morph。

本地类型提供结构依据：

- [BSFaceGenAnimationData](../extern/CommonLibSSE/include/RE/B/BSFaceGenAnimationData.h)：表达／修饰／口形／自定义的输入及 final values、眨眼阶段／计时和锁。
- [BSFaceGenNiNode](../extern/CommonLibSSE/include/RE/B/BSFaceGenNiNode.h)：头部自身的 animationData、Actor handle 和独立 downward update。
- [BSFaceGenBaseMorphExtraData](../extern/CommonLibSSE/include/RE/B/BSFaceGenBaseMorphExtraData.h)：形变相关顶点资源。
- [BSDynamicTriShape](../extern/CommonLibSSE/include/RE/B/BSDynamicTriShape.h)：动态几何数据／帧标识及锁。不是所有头部都可按同一布局直接解释。

仅拿到 `SetExpressionOverride` 的接口不证明本次调用已执行全部形变与上传。改变权重、生成形变、更新显示数据要分别观测。
所选 idle／HKX／OAR 替换也可能根本没有脸部表情输入；“无表情”不能直接证明 FaceGen 更新坏了。
保留 Actor 能维持它的面部资源关系，但仍需暂停时的独立更新入口。不能通过把复制头的 userData 指回 O 或共享 O 的可变权重来补齐。

### F00：确认画的是哪个头、状态归谁

1. 记录实际面板 pass 的头部 geometry／skin／根；区分 O 的源头、P 的 Actor 头和旧复制头。
2. 记录 P 的 FaceGen 节点、`GetFaceGenAnimationData()`、节点 animationData、Actor handle、morph 资源及动态几何身份。
3. 核对运行权重、计时与动态顶点数据是否与 O 共用；只读模型／TRI 资源共享不等于可变状态共享。
4. 可变状态所有权未明确前禁止写表情。只在 P 的 Actor 头设置参数而画面仍用旧复制头，预期不会同步；先接 R01，或明确另做复制头适配。

**通过**：状态与被绘制头部属于声明的目标，写入不会落到 O。缺状态或共享未排除记阻断，不直接试着调用源 Actor。

### F01：正常引擎中的已知表情夹具

1. 选择一个已知模型支持的 expression，例如 MoodHappy；准备中性→0.5→1.0→恢复原状态的有限对照。具体通道和值由包固定，并保留原参数。
2. 先在正常引擎更新下验证 P 的该通道确实能造成可见形变或可测顶点变化；不要用 O 的成功代替 P 模型支持证明。
3. 固定相机和头部基础姿态，记录输入权重、最终权重、形变／动态几何摘要及画面。每态观测约 2 秒，避免把头骨移动当成表情。
4. 同样选择一个已支持眨眼 modifier；需要口形时单独用一个已支持 phoneme 夹具。完整对话／音频驱动不属于本轮要求。

**通过**：目标与资源支持已确认，已知输入产生预期变化且可恢复。若正常更新下也无效果，先查目标／资源／输入，不归因暂停。

### F02：暂停时区分输入、权重求值与形变

前置 F00／F01 成立；表情诊断需要新包提供针对 P 的定向入口，未知调用不能直接上机试。

1. 暂停背包、关闭物理、冻结身体基础姿态。记录原表达／modifier／phoneme 权重及最终值、眨眼 timer／stage，建立 3 秒基线。
2. A：只改变同一已知表达输入，保持独立脸部更新关闭，观测约 2 秒；记录输入和 final values 是否变化、头部形变是否变化。
3. B：同样输入与目标，开启经调查的 P 脸部更新，观测约 2 秒；分别采输入／最终权重、形变数据、上传／draw 状态。具体求值／morph 调用由新包 manifest 说明，不默认一次 UpdateDownwardPass 就完成所有阶段。
4. 恢复原权重，再做固定眨眼通道；自动眨眼计时可另外验证冻结／继续／单步，不能仅靠保持非零权重假装自动眨眼。
5. 全程观测 O 的 FaceGen 权重、计时和必要几何；不能调用完整 Actor 世界更新来驱动表情。

**判读**：

| 观察 | 定位 |
| --- | --- |
| 没有脸部输入变化 | 动作没有该通道／参数未到目标，不能判 morph 故障 |
| 输入变化、最终权重不变 | 面部状态求值／过渡阶段待接入或条件阻断 |
| 最终权重变化、形变／动态几何不变 | 资源或 morph 应用阶段待定位 |
| 几何变化、画面不变 | 进入 F03 查上传、真实头部 draw 与缓存 |
| O 的状态变化 | 目标／共享状态错误，立即停止，不计通过 |

### F03：形变到实际 draw 的消费

1. 对照 F02 A/B 的同一头部，分别在 morph 前后、A4 pass 前、A5 draw 后记录 geometry 身份、动态数据／大小／帧标识、可安全解释的顶点变化和绑定资源。
2. 需要时做配对图形抓帧，确认实际头部 pass 使用了更新数据；CPU 指针可读／数据摘要变了不等于已上传。
3. 同 Actor 直绘时确认用的是 P 的动态头；复制头路线不能依赖 O 动态资源刚好被更新，不用复写 O 缓冲作为解决方案。
4. 形变类型不同的头部使用各自解释与证据。若没有可确认的动态几何布局，用受保护采样／抓帧定位，不猜顶点格式直接写。

**通过**：表达输入、最终权重、目标形变与实际图像建立链路，头部基础姿态保持对照，O 不受影响。

### F04：恢复、组合与生命周期

1. 恢复原状态并清除本轮预览 override，确认模型回到基线，没有把 P 的表情写到 O。
2. 在直绘与对应资源生命周期成立后，先组合身体动画＋脸部，再组合身体＋脸部＋单一物理后端，最后两后端；记录每阶段的目标和写入者。
3. 候选顺序是最终骨架应用、独立 FaceGen 状态／形变、物理输入／解算、动态几何／蒙皮准备、draw；实际顺序以调用链调查为准，FaceGen 更新不得再覆盖物理输出。
4. 暂停时只使用面板自己的脸部计时；失焦、关闭面板时停止不必要更新。换头／换树使旧 FaceGen 引用失效，按 generation 重绑。
5. R09 基础回收成立后再测重复开关／读档；未成立只做单对象短测。检查眨眼计时、override、动态几何和后端任务不残留。

**通过**：状态可恢复、组合无覆盖、资源引用与时钟独立。此项不自动包含完整语音口型或任意外观模组兼容。

## 5. 身体变形：独立于表情与物理的外观同步

本项记录的是克隆 Actor 未继承 O 的身体变形，不假定问题仅在暂停时发生，也不把它等同于旧复制图丢失 O 已生成的静态体型。
克隆 Actor 重新装配网格，复制基础 TESNPC 不保证继承原引用的运行时 morph／骨覆盖数据。
当前未发现显式同步这类状态；实际原因仍需结合所用体型系统、参数存储身份及网格观察验证。
基础体重、安装时生成的身体模型、运行时形变、额外骨缩放、动画与物理造成的瞬时轮廓变化分别记录。

### BM00：来源、目标与体型参数归属

1. 记录 O／P 的 Actor 和基础记录身份、性别／基础体重、实际身体及护甲模型、骨架、3D generation 与实际显示根。
2. 记录用户采用的体型方案及版本，明确形状来自固定模型、体重插值、运行时 morph、骨缩放或组合；不默认所有差异都是同一种 BodyMorph。
3. 若使用运行时系统，调查其参数／覆盖数据绑定到哪个引用或基础记录、何时应用；仅通过已确认接口只读取得当前生效值，不猜内部缓存。
4. 可变 morph 参数／顶点／骨覆盖不得与 O 共用；资源与状态来源未知则阻断同步实验。P 不得被另一个自动体型分配规则悄悄改成新随机体型。

**通过**：能解释 O 当前形状的来源以及 P 当前装配和形变身份。参数不可达时记录具体缺口，不用相同体重宣称体型一致。

### BM01：同姿态下比较实际身体形状

1. 从独立测试存档选择一个已知有明显身体变形的 O，使用已有的受支持身体样本；关闭本轮物理，固定表情、姿态和可比较的尺度／视角。
2. 分别观察未被装备覆盖的身体，以及一件已知适配该形变的贴身装备。不得仅通过一件宽松护甲遮挡差异。
3. 记录 O／P 的实际生效参数、身体网格身份／形状摘要和可比较截图；基础动作不同造成的轮廓变化先排除，不能为取景移动或改写 O。
4. 先只读比较，再对 P 应用经过调查的来源 morph／骨覆盖。应用接口、线程、阶段与数据所有权写入新包 manifest；未知入口不直接试。

**通过**：基础体重和声明支持的变形共同反映到 P 身体，数据与实际形状相符、O 保持不变。仅参数相等或调用成功不够；若参数一致但形状不同，继续定位模型兼容、morph 资源、应用与渲染消费阶段。

### BM02：装备、动画与换树保留

1. 在 P 的体型同步成立后开启动作，分别记录应用前／动画后／pass 前的体型状态。额外骨缩放实现的体型尤其要检查是否被 hkQsTransform 写入覆盖。
2. 按已确认安全流程单次更换身体／护甲装备，核对新装备支持相同 morph 资源与参数。装备缺适配记未支持，不能由身体正确外推任意护甲正确。
3. 3D generation 变化时重新确认节点和形变目标，按声明规则重应用；旧参数不能写入旧网格或旧骨架。
4. 生命周期门槛成立后再测关闭／重开和连续换装。检查新形状不被默认模板、随机体型规则或快照／绑定姿态恢复替换。

**通过**：动作运行、装备刷新和换树后体型仍与 O 当前生效形状一致，相关装备正确适配，没有无效引用或持续累积。

### BM03：隔离、恢复与后续组合

1. 用一个参数不同的第二测试样本分别验证；不要在 P 调试时修改 O 体型或共享基础记录。
2. 将 P 的某个已支持参数临时改变再恢复，确认 O 的参数／几何／骨覆盖均不变；写入前先满足 BM00 的所有权门槛。
