# S3：复制场景图上的独立 SMP／CBPC 游戏内验证

日期：2026-10-10。依据：[PRD 0.8 §6.5](player-panel-prd.md)。

这是待实现测试包的操作与回传协议，**当前 HKX12 DLL 尚不能执行本单**。先完成 V00，确认新包提供相应入口后再上机；没有入口的项目填写“阻断”，不要用现有 F2 的骨骼摆动代替物理结果。

## 1. 本轮要回答的问题

在不把 P 放入游戏 Cell／WorldSpace、不推进 O 的条件下，能否给副本创建实际 SMP／CBPC 实例，以自己的 dt 更新，并把结果稳定保留到面板绘制？

先用确定性基础运动测试物理，随后以真实 HKX 替换输入。基础运动只能推动锚点／驱动骨，不能直接推动被验收的物理输出骨。程序化输入在此仅是测量工具，不是展示动作或物理求解器的替代交付。

## 3. 游戏内通用准备

1. 安装 manifest 对应的新包；避免同时加载旧 CharacterPanel／Probe。核对日志中的构建与两个后端身份。
2. 从独立测试存档开始，选一个原本在正常游戏中确实有效的 SMP 装备与一个 CBPC 身体节点。记录网格、骨架和实际配置；没有相应配置的 UBE 不作为成功预期样本。
3. 在世界正常运行时观察一次 O 的物理，确认该样本／配置有效。这是测试夹具检查，不通过面板命令额外推进世界。
4. 选择附近一个可只读观察的 NPC，在打开背包前记下 O／NPC 的身份和第三人称骨架。NPC 图不可用时记录，不能声称已验证 NPC 隔离。
5. 打开暂停 InventoryMenu，等待装备装配完成。确认 UI 暂停状态，在无装备操作下观测 5 秒的 O／NPC 基线；记录动画进度和选定物理骨变换的自然变化范围。
6. 捕获一份 P 并显示。固定相机、照明、装备、根位置，风关闭。后续对照复用这份 P，每次只重置声明的测试状态。
7. S1 未通过时，不反复 F7、不做刷新压力测试、不读档复用该对象。短测结束保存日志并结束进程；不要将本轮没有析构写成“释放成功”。

## 4. 逐步操作与判据

每一步开始时标记 V 编号、条件和 step ID。推荐锚点输入为绕声明轴 ±5°、0.5 Hz、3 个周期，实际轴和幅度由骨架／配置在发包前确认；不临场扩大振幅掩盖错误。用模拟时间计周期，用真实时间记录观察窗口。

### V01：只验证基础输入与引用隔离

1. SMP／CBPC 都关闭，基础输入固定，观察 5 秒并保存基线。
2. 启动受控锚点输入 3 个周期，确认 P 的锚点及所需后代随输入移动；记录实际变化，不重复旧蒙皮槽位猜测。
3. 冻结基础输入，确认冻结在当前姿态，而非突然跳回捕获姿态；两个求解器仍关闭。
4. 对照 O／NPC 的暂停读数。输入写入清单与 P 节点集合必须相符；物理输出骨不得被探针独立赋予摆动。

**通过**：P 只体现基础驱动，来源无额外推进，图／skin／节点引用隔离成立。失败先查源引用、骨名分支、输入覆盖；未通过不创建物理实例。

### V02：SMP 系统创建，不步进

1. 重置基础姿态，CBPC 关闭，选择 manifest 指定的 SMP 头发或衣物。
2. 创建预览 SMP 实例并保持物理冻结，保存解析／绑定报告。
3. 核对动态骨、运动学锚点、刚体／约束、网格碰撞数量与预期；检查所有节点、skin 和模型指针均属于 P。
4. 保存零步状态和画面。确认没有将此系统加入主世界对象集合，也没有更改主世界的 suspend 状态。

**通过**：实际系统和必要绑定齐全，状态归预览句柄所有；创建成功但动态骨为零不能算物理通过。配置找不到或必要骨缺失记“阻断”，查配置覆盖、骨名重命名／分支和装备附着路径。

### V03：SMP 步进、惯性和冻结

1. A：重置同一初态，SMP 不步进，输入运动 3 周期；保存基础驱动结果。
2. B：重置同一初态，SMP 步进，重复同一输入；记录锚点、动态骨、速度／约束状态、物理后与 pass 前的结果，录像或连续截图。
3. 冻结基础输入 5 秒，保持 SMP 推进。观察物理响应及其随后变化；有正阻尼的声明配置应显示总体衰减，不要求每一帧位移单调减小。
4. 冻结全部预览 3 秒，再执行一次单步；检查冻结期间时间／状态保持，单步恰好推进一个步长。
5. 全程对照 O／NPC 暂停基线，禁止解除 FSMP 主模拟暂停来取得效果。

**通过**：B 有超过基础输入的真实求解响应，冻结输入后状态继续演化，物理结果到 draw 前未被恢复；全部冻结停止更新，单步正确，O／NPC 保持基线。
若 B 与 A 相同，依次查系统是否动态、dt／累计时间、active／suspend、节点绑定、输出写回、后续 pose 覆盖。不能仅用 step 计数增加或“头发在动”判成功。

### V04：SMP 身体碰撞

1. 选一条能让被测发束／衣物进入有效身体碰撞区域的受控输入路径。记录目标碰撞体、组／掩码、空间范围和预计接触时刻；若不会相交，换夹具后重新声明。
2. A：SMP 步进、身体碰撞关闭，重置初态并执行路径，保存穿透／接触距离。
3. B：只开启这组身体碰撞，重置同一初态、重复路径，保存接触对、响应及画面。
4. 核对碰撞集合只包含 P 的相关对象，检查 O／NPC 未成为预览碰撞对象。

**通过**：B 的接触发生于已声明区域，响应与画面差异吻合，既定穿透改善。约束下本来就不会接触时记“无有效接触，实验无效”，不能据此判碰撞模块失败。并不要求任何衣物绝不穿模。

### V05：CBPC 单节点

1. SMP 关闭，选择 manifest 中一个实际配置支持、可见网格具有非零权重的 CBPC 输出骨及其驱动锚点。
2. 创建预览 CBPC 实例，核对实际条件命中、参数、体重插值、碰撞体与节点状态键；预览 ID 不复用 O 的 FormID，状态表不借用 O／NPC 的条目。
3. 重复 V03 的 A/B、冻结输入 5 秒、冻结全部预览与单步流程；保存节点位移／速度、物理后和 pass 前变换。
4. 若本轮声明 CBPC 碰撞支持，增加与 V04 相同的有效路径／碰撞开关对照；未做碰撞测试时，仅记录节点运动前置通过，不宣称完整 CBPC 碰撞兼容。

**通过**：由实际 CBPC 适配求解器产生额外响应，配置与状态隔离正确、输出未被覆盖、暂停来源不动。副本基础运动本身导致输出位置变化不足以通过；版本差异未核对则限定为已测试源码／模块版本。

### V06：两后端组合

1. V03–V05 已通过后，确认同一套身体、装备和配置可给两个后端明确分工，例如 CBPC 身体节点与 SMP 发束；不要求同一骨同时支持两者。
2. 在同一初态、输入和相机下依次测“只开 CBPC”“只开 SMP”“两者开启”，保存相同模拟时刻的状态和画面。
3. 转储动态输出节点清单、最终写入者及执行顺序。若 SMP 碰撞依赖 CBPC 改写的身体状态，明确传递时点与同步方式。

**通过**：组合中两套响应持续存在，无未经设计的双写、状态串用或覆盖。抖动先查骨骼职责、重复 dt、碰撞输入时序；不能通过把其中一套效果关到零宣布兼容。

### V07：时间、帧率、失焦与展示空间

1. 对已通过的单后端先做本项，再对组合做。每个对照重置初态，以同一输入和固定子步分别在 30／60／120 FPS 上限运行相同模拟时长，在 manifest 指定时刻采样。
2. 比较累计模拟时间、子步、锚点、动态骨与接触状态；显示帧率不同不能导致多次 draw／pass 重复推进。达不到目标帧率时记录实测值和“未覆盖目标”，不伪造覆盖。
3. 冻结全部预览、单步、继续；再分别改变动画速度和物理速度，核对包中声明的倍率规则，而非默认两个时钟都变。
4. 切出游戏 3 秒后切回，记录实际焦点事件与补步；按 manifest 的冻结／恢复策略验收，不得一次追赶全部空档导致爆炸。
5. 改变相机取景使人物显示大小变化，确认模拟骨架尺度／碰撞尺寸不变；再按包中指定方式旋转 90°。
6. 相机旋转应只改变视角；若选择物理根旋转，检查统一变换／重置规则、碰撞对齐与参考姿态。旋转不应反复重置状态造成持续跳动。

**通过**：相同模拟时间的数值在预先确定容差内，长帧处理、冻结和单步正确，取景不改变物理尺度。先报告误差与单位；不以相近观感代替时间一致性。

### V08：接入真实 HKX

前置：[H03／H04](s2-hkx-next-work-package-2026-10-10.md) 已通过、物理前置通过。没有实际 HKX 采样对象时填“阻断”，V03 的受控输入结果保留。

1. 选一段已确认的实际 HKX clip，记录资源／binding／轨道映射与根处理，关闭物理建立动画参考。
2. 相同初态、clip 和时间分别只开 CBPC、只开 SMP、两者开启，核对基础动画骨与物理输出骨的分工及画面。
3. 冻结 HKX 基础姿态，保持物理时间；再冻结全部预览，随后继续，核对两个时钟的区别。
4. 切换到第二段已支持动作，测试过渡和声明的状态重置规则；动画事件不能在世界触发攻击／施法等行为。
5. 采样物理前／后／pass 前数据，检查没有一次动画全骨覆盖或 `pose()` 复位抹掉物理输出。对照 O／NPC 基线。

**通过**：真实动作及附加物理均有效，时序和隔离正确；录制回放、只验证一段姿态和程序化输入不能代替动作切换验收。单 clip 不能无条件与含 IK／混合／物理的源最终姿态逐骨相等。

### V09：换装与物理重建

前置：S1 安全回收和 V10 的后端解绑／图释放已通过；否则本项不运行。

1. 固定动作与时钟规则，装备 A 具有明确 SMP 系统；B 是另一套已支持装备或无该 SMP 系统的对照。
2. 在暂停背包中通过正常装备操作 A→B→A，每次等待实际装备确认和 P 更新。**不按 F7 手动重新捕获**。
3. 核对请求／提交 generation、新网格／配置、旧系统解绑、新碰撞及节点数量；对新装备运行短运动与冻结输入测试。
4. 连续请求 A→B→C，观察最终 C；记录旧加载完成是否被丢弃，不能用延长等待隐藏旧结果覆盖。
5. 记录动画是续接、重采样还是按声明规则重置，物理状态如何初始化。不能复用旧装备速度／约束引用导致飞散。

**通过**：最终装备与游戏生效结果一致，物理绑定正确，无旧节点引用；装配期间 O 的允许更新另记。O／NPC 的隔离判断在装配结束、无装备操作的观察窗口进行。
失败查代次、骨重命名／merge、配置选择、线程屏障及旧系统卸载顺序；手动捕获正确仅证明静态装备同步。

### V10：注销与实际回收

先做 A，B 只有 S1 释放路径具备实现与证据后才能做；任何阶段崩溃立即停止，不盲试后续操作。

**A．保留图，解绑后端**

1. 物理运行时提出销毁请求，确认停止调度并等待所有 worker 完成。
2. 解除刚体／约束、碰撞集合、节点和配置状态引用，保存解绑后的任务／实例／分配计数。
3. 保留 P 图并静态显示 5 秒；旧句柄的 step 必须被拒绝，不能再有 worker 或碰撞回调访问旧系统。
4. 后端实际资源计数应回到声明基线；该阶段不涉及图析构，因此成功不代表 S1 已通过。

**B．后端先解绑，再真正释放图**

1. 确认 A 的屏障与引用解除后，实际销毁 P，记录图／skin／相关分配回收与渲染引用解除。
2. 基础释放成立后，执行 5 次完整创建／显示／关闭；分别记录创建前、关闭后、下一次创建前的资源。
3. 再按独立场景测试读档、经主菜单读档、返回主菜单；旧请求／句柄失效，新会话不能显示或更新旧副本。
4. 内存／显存可能有加载缓存，结合后端／图实际分配计数判定。记录预热与观察窗口，资源应收敛；只看工作集一次下降不足以证明回收。

**通过**：任务完成、引用清除、实际释放证据与资源稳定同时成立。PARK、删除记账指针和无崩溃都不足以通过。

| 绑定 | P root／输出骨／锚点／网格身份、归属检查、刚体／约束／碰撞／节点数量、配置选择与跳过原因 |

| 状态 | 基础输入、物理后、pass 前变换，动态速度／可用求解状态、碰撞对／接触；采样只读、不手写蒙皮缓存 |
| 来源隔离 | O／NPC 的暂停基线、动画进度与骨变换变化；观察窗口是否含装配／正常恢复世界事件 |
| 生命周期 | 任务调度／完成、系统创建／解绑／拒绝旧句柄、实际分配／释放／停放数量、渲染引用与异常 |

每轮保留完整日志、manifest、匹配 PDB 和配置；A/B 截图或视频标记实际模拟时间和控制状态。碰撞分析需要接触证据；输出被覆盖需要物理后与 pass 前配对证据。日志可低频采样，但创建／销毁／异常与状态切换事件不得丢失。
